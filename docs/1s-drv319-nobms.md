## 固件行为

以原厂 DRV319 为基础，保留速度、电流、起步、刹车及 KERS 参数常量；约 5 km/h 起步门槛仍生效。
移除对小米 BMS 的轮询、发送及相关故障/降额依赖，保留主板 ADC 电压限制、主板温度与输入故障检查。

电量显示固定为 **80% 假值**，不是实际电量估算；总电压取自主板 ADC。
来自仪表端的合法 BMS 只读请求由主板本地回答，使用原厂封包、校验和 UART 发送代码。
其余字段保留缓存/初始值，不提供真实单体电压、温度、容量、BMS 身份或升级/写入仿真。
外接电池须由自身 BMS 提供保护，小米 BMS 数据线应断开。

## Win11 / ST-Link Utility 烧录

1. 加载上面的 **64 KiB 完整 BIN**，地址填写 **`0x08000000`**。
2. 下载并执行 Verify。
3. 断开调试器，彻底断电后重新开机，再检查仪表与驱动。

该镜像包含 Bootloader、应用和个性化车辆数据。解除读保护可能擦除整个主 Flash，
因此这种情况下只写 `0x08001000` 的应用不能完成恢复。不要为了此次下载再次解除读保护。
换主板时，必须使用目标主板自己的 UID 重建；不能直接沿用此处的个性化镜像。

布局按 [CamiAlfa 1S 恢复脚本](https://github.com/CamiAlfa/M365_DRV_STLINK/blob/b4e03683d5f9fe6981a615855e2e3d34c36ab844/flash_m365_1S.py#L55-L75)核对：

| 完整镜像偏移 | MCU 地址 | 内容 |
| --- | --- | --- |
| `0x0000` | `0x08000000` | Bootloader |
| `0x1000` | `0x08001000` | DRV319 应用 |
| `0xF800` | `0x0800F800` | 车辆数据模板及 UID、序列号、里程 |

## 一步重建完整镜像

使用 Python 3.10 或更新版本，在仓库根目录执行：

```bash
python -m pip install -r requirements-1s.txt
python build_1s_recovery.py rebuilt-full.bin --uid-words 066FFF57 48557886 67092140 --serial 25699/38039257 --replacement-serial
```

此命令应生成与已确认 BIN 相同的字节内容。构建器拒绝覆盖已有输出和报告。
所有必要输入保存在 `recovery_assets/1s/`，不需要临时下载目录。

- `--uid-words` 为从 `0x1FFFF7E8` 起按地址递增读取的三个 32 位十六进制字；也可使用 `--uid-file` 传入原始 12 字节文件。
- `--serial` 使用原车序列号；若经授权使用替代号，加 `--replacement-serial` 标记来源。
- `--km` 可提供已知里程；省略时明确记录为未知并置零。
- `--stock` 可按需生成未修改原厂应用的完整对照镜像，仍会检查 BMS。

## 代码与校验

- `build_1s_recovery.py`：唯一命令行入口，生成完整镜像和审计报告。
- `drv319_nobms.py`：精确匹配原厂文件 SHA-256 后应用补丁。
- `drv319_bms_proxy.py`：固定电量、ADC 电压及 BMS 只读应答汇编。
- `recovery_assets/1s/`：原厂应用、引导程序、车辆数据模板及来源校验值。

```bash
python -m unittest test_drv319_nobms test_drv319_bms_proxy test_1s_recovery -v
```

测试覆盖精确输入校验、补丁范围、驱动/制动请求、起步门槛、输入故障、欠压恢复、
认证消息、收包校验、回复帧、队列边界、UART 数据寄存器写入、完整布局及原厂运行时数据初始化。
并直接比较重建结果与仓库中已确认的完整 BIN。

ARM 仿真未模拟真实电机动态、ADC 转换或 UART 电气时序。单车实测反馈与这些测试互为补充，
不构成完整 BMS 仿真或所有硬件组合的保证。
